# Yiimp2 Security Configuration Guide

## Overview

Yiimp2 uses environment variables for all security-critical configuration, making it easy to deploy securely in Docker environments while following security best practices.

## Quick Start

### 1. Generate Secure Keys

Use the provided script to generate secure random keys:

```bash
./generate-secure-keys.sh
```

This will:
- Generate a cryptographically secure cookie validation key
- Create or update your `.env` file
- Provide security recommendations

### 2. Configure Environment

Edit `.env` and set your configuration:

```bash
# Required: Set strong passwords
DB_ROOT_PASSWORD=<strong-random-password>
DB_PASSWORD=<strong-random-password>

# Required: Cookie validation key (generated by script)
YIIMP_COOKIE_VALIDATION_KEY=<64-char-hex-string>

# Optional: HTTPS configuration
YIIMP_FORCE_HTTPS=false  # Set to 'true' if behind SSL proxy

# Optional: Session configuration
YIIMP_SESSION_TIMEOUT=3600  # 1 hour
YIIMP_SESSION_NAME=YIIMP2SESSID

# Optional: Debug mode (false for production)
YIIMP_DEBUG=false
```

### 3. Deploy

```bash
docker-compose up -d
```

## Configuration Reference

### Required Settings

#### YIIMP_COOKIE_VALIDATION_KEY

**Purpose:** Cryptographic key for cookie validation and CSRF protection

**Generation:**
```bash
openssl rand -hex 32
```

**Security:**
- MUST be unique for each installation
- MUST be kept secret
- SHOULD be rotated periodically
- MUST NOT be committed to version control

**Example:**
```bash
YIIMP_COOKIE_VALIDATION_KEY=a1b2c3d4e5f6789012345678901234567890abcdef1234567890abcdef123456
```

### HTTPS Configuration

#### YIIMP_FORCE_HTTPS

**Purpose:** Force HTTPS mode for secure cookies

**Values:**
- `true` - Force HTTPS mode (use when behind SSL/TLS proxy)
- `false` - Auto-detect HTTPS (default)

**Auto-Detection:**
The application automatically detects HTTPS from:
1. `$_SERVER['HTTPS']` - Direct HTTPS connection
2. `$_SERVER['HTTP_X_FORWARDED_PROTO']` - Proxy forwarded protocol
3. `$_SERVER['HTTP_X_FORWARDED_SSL']` - Proxy SSL indicator

**When to use `true`:**
- Behind HAProxy with SSL termination
- Behind Nginx reverse proxy with SSL
- Behind any SSL/TLS terminating load balancer

**Example HAProxy Configuration:**
```haproxy
frontend https_front
    bind *:443 ssl crt /etc/ssl/certs/yiimp.pem
    http-request set-header X-Forwarded-Proto https
    http-request set-header X-Forwarded-SSL on
    default_backend yiimp_backend

backend yiimp_backend
    server yiimp2 127.0.0.1:8090 check
```

### Session Configuration

#### YIIMP_SESSION_TIMEOUT

**Purpose:** Session timeout in seconds

**Default:** `3600` (1 hour)

**Recommendations:**
- **High Security:** `900` (15 minutes)
- **Standard:** `3600` (1 hour)
- **Convenience:** `28800` (8 hours)

**Example:**
```bash
YIIMP_SESSION_TIMEOUT=3600
```

#### YIIMP_SESSION_NAME

**Purpose:** Session cookie name

**Default:** `YIIMP2SESSID`

**When to change:**
- Running multiple Yiimp2 instances on same domain
- Avoiding conflicts with other applications

**Example:**
```bash
YIIMP_SESSION_NAME=YIIMP2_PROD_SESSION
```

### Application Configuration

#### YIIMP_DEBUG

**Purpose:** Enable debug mode

**Values:**
- `true` - Enable debug mode (development only)
- `false` - Disable debug mode (production)

**Debug Mode Enables:**
- Detailed error messages with stack traces
- Yii2 debug toolbar
- SQL query logging
- Performance profiling

**Security Warning:**
⚠️ **NEVER enable debug mode in production!** Debug mode exposes:
- Database queries and structure
- File paths and system information
- Stack traces with code snippets
- Configuration details

**Example:**
```bash
# Development
YIIMP_DEBUG=true

# Production
YIIMP_DEBUG=false
```

## Security Best Practices

### 1. Cookie Validation Key Management

✅ **DO:**
- Generate unique keys for each environment
- Use `openssl rand -hex 32` for generation
- Store in environment variables or secrets management
- Rotate keys periodically (e.g., every 90 days)
- Keep keys secret and secure

❌ **DON'T:**
- Use default or example keys
- Commit keys to version control
- Share keys between environments
- Use weak or predictable keys

### 2. HTTPS Configuration

✅ **DO:**
- Always use HTTPS in production
- Set `YIIMP_FORCE_HTTPS=true` when behind SSL proxy
- Ensure proxy forwards proper headers
- Use valid SSL certificates (Let's Encrypt, etc.)
- Enable HSTS headers in proxy

❌ **DON'T:**
- Run production without HTTPS
- Use self-signed certificates in production
- Forget to configure proxy headers
- Mix HTTP and HTTPS content

### 3. Session Security

✅ **DO:**
- Use shorter timeouts for admin panels
- Enable httponly flag (enabled by default)
- Enable secure flag for HTTPS (auto-enabled)
- Use SameSite=Lax for CSRF protection (auto-enabled)
- Monitor session storage size

❌ **DON'T:**
- Use excessively long timeouts
- Disable httponly or secure flags
- Store sensitive data in sessions
- Ignore session cleanup

### 4. Debug Mode

✅ **DO:**
- Use debug mode only in development
- Use proper logging in production
- Monitor error logs regularly
- Implement proper error handling

❌ **DON'T:**
- Enable debug mode in production
- Expose error details to users
- Ignore error logs
- Rely on debug mode for troubleshooting production

## Troubleshooting

### CSRF Validation Errors

**Symptom:** "Unable to verify your data submission"

**Solutions:**

1. **Verify cookie validation key is set:**
   ```bash
   docker-compose exec yiimp2-web env | grep YIIMP_COOKIE_VALIDATION_KEY
   ```

2. **Check session cookies:**
   - Open browser developer tools
   - Check Application/Storage → Cookies
   - Verify `YIIMP2SESSID` cookie exists
   - Check cookie flags (HttpOnly, Secure, SameSite)

3. **Restart containers:**
   ```bash
   docker-compose down
   docker-compose up -d
   ```

4. **Clear browser cookies:**
   - Clear all cookies for the domain
   - Try in incognito/private mode

### HTTPS Detection Issues

**Symptom:** Cookies not marked as secure despite using HTTPS

**Solutions:**

1. **Check proxy headers:**
   ```bash
   # In PHP
   var_dump($_SERVER['HTTP_X_FORWARDED_PROTO']);
   var_dump($_SERVER['HTTP_X_FORWARDED_SSL']);
   ```

2. **Force HTTPS mode:**
   ```bash
   YIIMP_FORCE_HTTPS=true
   ```

3. **Configure proxy to send headers:**
   ```haproxy
   # HAProxy
   http-request set-header X-Forwarded-Proto https
   http-request set-header X-Forwarded-SSL on
   ```

### Session Timeout Issues

**Symptom:** Users logged out too quickly or sessions lasting too long

**Solutions:**

1. **Adjust timeout:**
   ```bash
   # Shorter timeout (15 minutes)
   YIIMP_SESSION_TIMEOUT=900
   
   # Longer timeout (4 hours)
   YIIMP_SESSION_TIMEOUT=14400
   ```

2. **Check PHP session configuration:**
   ```bash
   docker-compose exec yiimp2-web php -i | grep session
   ```

3. **Verify session storage:**
   ```bash
   docker-compose exec yiimp2-web ls -la /tmp/
   ```

## Key Rotation

### When to Rotate Keys

- Every 90 days (recommended)
- After security incident
- When employee with access leaves
- When key may have been exposed

### How to Rotate Cookie Validation Key

1. **Generate new key:**
   ```bash
   openssl rand -hex 32
   ```

2. **Update .env:**
   ```bash
   YIIMP_COOKIE_VALIDATION_KEY=<new-key>
   ```

3. **Restart containers:**
   ```bash
   docker-compose down
   docker-compose up -d
   ```

4. **Note:** All users will be logged out and need to re-authenticate

## Monitoring and Auditing

### Security Checklist

- [ ] Cookie validation key is unique and secure
- [ ] HTTPS is enabled in production
- [ ] Debug mode is disabled in production
- [ ] Session timeout is appropriate for security requirements
- [ ] Database passwords are strong and unique
- [ ] .env file is not committed to version control
- [ ] Error logs are monitored regularly
- [ ] Security updates are applied promptly
- [ ] Keys are rotated periodically
- [ ] Access logs are reviewed regularly

### Log Monitoring

Monitor these logs for security issues:

```bash
# Error logs
tail -f log/yiimp2/yiimp2-error.log

# Access logs (if configured)
docker-compose logs -f yiimp2-web

# Database logs
docker-compose logs -f yiimp2-db
```
